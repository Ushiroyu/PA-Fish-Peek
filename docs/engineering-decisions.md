# 关键设计决策

## 结构化规则与文档检索分别处理

鱼竿白名单、等级、地点掩码与环境分数可以直接计算，因此交给规则工具；文档负责说明计算含义、未知条件和操作方法。模型通过工具获得候选，再引用检索段落解释结果。

这样可以重复同一条件下的计算，也能区分数据更新、检索遗漏和模型解释错误。领域工具的分数是排序值，不能换算为服务器出鱼概率。

## 采用 BM25 检索中文说明

当前知识库由篇幅较短的领域说明组成，鱼名、鱼竿标识、天气名和规则术语是常见查询词。按标题分块，使用中文单字、双字词和英文标识计算 BM25 分数，部署时无需额外的模型服务。

这项选择优先保证术语检索、可复现性和来源定位。相同含义的不同表达可能缺少词面重合，适合通过真实问题集观察漏召回，再决定是否增加同义词、语义检索或重排。检索策略变化应与相同问题集对照。

## MCP 与 HTTP 共用工具注册表

`ToolRegistry` 负责 Schema 校验和领域执行。FastAPI、MCP 以及兼容接口 Agent 都调用相同工具，避免三个入口维护不同的候选规则。

MCP 还将字段范围直接暴露给模型，例如检索条数为 1–6，事件条数为 1–50。协议侧约束与内部校验同时保留：前者帮助模型形成有效请求，后者保护直接调用工具注册表的入口。

## 工具保持只读

查询只需要已附带的版本数据、中文说明和固定事件文件，因此不提供任意文件路径、命令执行或游戏操作参数。匿名事件通道把插件与分析服务分开，模型无需接触游戏原生内存和账号信息。

未来需要写入操作时，应另行定义输入、授权范围和可回滚行为，不能把现有查询工具改为任意执行入口。

## 模型调用预算与失败处理

网页兼容接口 Agent 对步骤、工具次数、单次输出和总耗时设限。参数错误作为结构化结果返回，模型可以调整输入；临时请求错误最多重试一次。重复调用超过限制时停止，避免无效循环。

Trace 记录工具名、状态和耗时，便于定位失败环节。它不保存密钥和原始提示。桌面模型调用由桌面客户端管理，本项目提供的 MCP 与网页 Agent 的预算、Trace 分别记录。

## 引用核验与回答质量分别检查

网页 Agent 为工具和检索结果分配引用 ID，并检查回答是否使用已提供的 ID。演示核验脚本则检查真实客户端事件中的工具结果、查询条件、来源和回答分数。

来源存在说明回答能够追溯，但不能单独证明回答完全受来源支持。因此自动化检查、实际模型演示与人工核对分别记录。自动回归样例通过率也不能替代实机鱼种命中率。

## 用版本快照与测试管理更新

`export-catalog.py --check` 对照插件内置表和随包快照，防止修改源码后遗漏更新工作台数据。领域回归固定白名单、等级、地点、季节和天气边界；MCP 子进程测试检查实际协议与字段范围；跨平台 CI 检查安装、规则与检索行为。

游戏更新后，原生读取、插件显示与现场事件仍由实机场景验收记录确认。数据快照测试解决的是工作台计算与版本数据的一致性。
