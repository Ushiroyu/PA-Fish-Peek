# 中文检索评测与改进记录

本轮采用 60 条离线场景问句，比较同一资料版本上的原始 BM25 与错误码规范化检索。评测不调用模型，结果衡量检索和排序；领域规则与真实模型调用分别保留自己的验证记录。

## 资料与相关性标签

知识资料共 5 份 Markdown、21 个有效段落。新增内容来自项目现有代码和设计文档，覆盖工具使用、当前状态与澄清、调用预算、重试、Trace、引用、数据快照与事件轮转。来源映射及资料版本保存在 `assistant/fishpeek/knowledge/sources.json`。

问句分为直接提问、同义表达、简称与标识、多段依据、条件缺失、无直接答案六组，每组 10 条。每条有相关段落标签和标注理由，见 `assistant/fishpeek/data/retrieval_cases.json`。这些是依据现有资料设计的场景样例，供维护者逐条复核，不作为线上用户分布或独立人工盲测。

标签使用“文件名#标题”，避免仅因行号变化而丢失相关性身份；实际检索结果仍返回路径与行号。重复问句、重复标签、缺少依据、未知段落、资料版本不匹配均会使评测失败。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| Precision@K | 前 K 条中被标注为相关的条数 / K；不足 K 条的位置按不相关处理 |
| Recall@K | 前 K 条中相关段落数 / 该问题标注的全部相关段落数 |
| Hit@K | 前 K 条是否至少出现一个相关段落 |
| MRR@K | 前 K 条中第一个相关段落排名的倒数，再按问题平均 |
| 无答案空检索率 | 无直接答案样例中返回空集合的比例，单独统计 |

前四项仅对 50 条有相关性标签的问题进行宏平均，K 取 1、3、4、6。未列入标签的段落在本轮二元标注中视为不相关；相关性判断仍需维护者复核。检索指标定义参考 [Elastic 官方排序评估说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval)，本项目直接实现计算，无需部署额外检索服务。

无答案样例不进入 Recall 或 MRR 分母。检索返回“不能将分数当概率”等边界文段可能帮助澄清问题，因此空检索率不等于拒答准确率，也不能将返回文段直接判为模型编造。报告逐条列出实际返回，便于后续判断。

## 同资料对照结果

资料版本：`knowledge-2026-10-23.2`；问题集：`retrieval-scenarios-1`。

| 策略 | Precision@4 | Recall@4 | Hit@4 | MRR@4 | 无答案空检索率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始字符与双字词 BM25 | 0.3000 | 0.9400 | 0.9600 | 0.8450 | 0% |
| 增加错误码规范化 | 0.3050 | 0.9600 | 0.9800 | 0.8517 | 0% |

原始分词把 `0xc0000005` 与省略前缀的 `c0000005` 当成不同英文标识。规范化在文档和查询中加入一致的十六进制标识，同时保留原词，使简称错误码能匹配诊断段落。原始策略保留为评测选项，便于在同一资料和标签上复现对照。

该改动在本问题集上改善了错误码查询，整体 Recall@4 提升 2 个百分点；这是公开场景集上的迭代观察，不能直接视为未知问题上的泛化提升。文档数、问句数、Recall、排序分数均不代表生成回答准确率。

## 已定位的待复核项

- “服务偶尔限流了会自动再试吗”：前四条未出现预期重试段落，属于同义表达召回不足。
- “c0000005 在哪个模块出过”：加入规范化后，预期诊断段落进入前四，但还不是第一条。
- “没认出鱼竿能直接随便换一根继续算吗”：前四条有未知条件说明，但缺少严格查询与插件回退的完整依据。
- 10 条无直接答案问题均返回了文段，需要区分有帮助的边界说明和无关噪声，再评估澄清或拒答策略。

完整分组和逐条排名见[本轮报告](evaluation/retrieval-report.md)。报告共列出 23 条需复核样例，涵盖排名靠后、多段依据不完整以及无答案文段检查；它们不统一按“测试失败”计数。

## 复现与回归

仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m fishpeek.evaluate_retrieval --strategy baseline --output artifacts\retrieval-baseline.json
.\.venv\Scripts\python.exe -m fishpeek.evaluate_retrieval --check-reference --output artifacts\retrieval-evaluation.json
.\.venv\Scripts\python.exe -m pytest assistant\tests -q
```

JSON 包含语料段落、标注、实际排名、分组指标、单次本地检索耗时和复核标记；同目录 Markdown 提供可读报告。耗时不包含索引构建与模型请求，不能作为完整问答性能结论。

`retrieval_reference.json` 保存显式冻结的参考指标、段落和标注清单。CI 检查资料与标签是否变化，并比较四个截断位置的指标是否下降；版本、资料或标注变化必须显式复核参考记录，不会自动接受较差结果。基线没有要求所有场景命中，已知问题仍保留在报告中。

后续先使用未参与本轮调整的新问句复核，再评估同义词规范化、检索融合或重排是否带来实际收益。
