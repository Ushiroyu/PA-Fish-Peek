# 后续规划

## 使用体验

- 优化多人同时咬钩时的玩家映射、提示顺序和重复消息处理。
- 持续适配鱼竿、鱼种、钓点和天气变化。
- 丰富显示选项、快捷键与日志诊断信息。
- 按游戏版本整理兼容性、场景测试与更新记录。

## 模块与数据

- 提取独立的候选规则模块，集中管理等级、地点、竿型和环境匹配。
- 为候选解释保留输入条件、筛选过程、排序依据和回退原因。
- 增加事件快照与离线回放，支持同条件复现与回归检查。
- 使用版本化数据存储管理鱼种、鱼竿、地点和天气信息。

## 工具接口

- 提供候选查询、解释、版本比较与事件读取接口。
- 设计只读 MCP 工具：`query_candidates`、`explain_candidate`、`compare_versions`、`read_events`。
- 统一输入输出 Schema、参数校验、读取路径限制与结构化错误。
- 提供独立示例数据与接口演示。

## 智能查询与评测

- 围绕钓鱼信息查询设计问题理解、工具选择与结果校验流程。
- 为模型调用设置步骤、超时与成本预算，完善失败处理。
- 结构化条件使用规则与数据库；说明文档与故障资料结合检索和来源引用。
- 建立人工核对的问题集，覆盖候选查询、解释、版本变化与异常情况。
- 记录任务完成率、工具成功率、答案依据、延迟与成本。
- 增加调用追踪、执行回放与工具权限边界检查。

各项规划围绕可演示、可解释、可复现的使用场景推进。
