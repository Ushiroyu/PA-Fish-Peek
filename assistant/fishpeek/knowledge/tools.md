# 查询工具与使用边界

## 查询与解释的分工

query_candidates 根据显式鱼竿、模式、等级、地点、季节、时间和天气计算候选。explain_candidate 针对一个鱼名返回是否保留、排除原因、环境匹配和排序分数。需要精确名单、数值或排除原因时，应调用规则工具；知识检索提供计算方法和使用说明，不替代规则计算。

## 检索与事件参数范围

search_knowledge 的 limit 为 1–6，默认 4；read_runtime_events 的 limit 为 1–50，默认 10。超出范围会被参数校验拒绝，不能通过增加条数读取任意文件。工具只读取配置中的匿名事件位置。具体鱼竿名称、UID 或 GUID 可通过 list_rods 查找。

## 桌面工具与网页问答

MCP 入口由桌面客户端中的模型调用六个只读工具；网页本地模式用规则结果与检索段落组织答复。网页模型模式则通过另外配置的 OpenAI 兼容接口执行多步工具调用。MCP 演示与网页供应商接口测试分别记录，不能相互替代。

## 当前状态与条件澄清

查询输入中的季节、天气和地点是用户给定条件，不自动代表当前现场。匿名事件包含等级、体型、时间和场景，不包含当前鱼竿、完整天气或真实鱼种结论。用户只问“我现在会钓到什么”而没有条件时，需要询问鱼竿、等级、钓点和环境，不能凭检索段落推断实时状态。
